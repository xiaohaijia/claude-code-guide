# 爆款视频脚本写作 Skill

## 触发条件
当用户要求写视频脚本、短视频脚本、爆款视频内容时触发。

## 写作前：必须先问用户

1. **视频主题是什么？**（核心产品/工具/知识点）
2. **目标平台？**（YouTube / B站 / 小红书 / 抖音，不同平台语气和节奏不同）
3. **目标受众？**（小白/进阶/专业，决定技术深度）
4. **视频时长预期？**（30秒短平快 / 3-5分钟中等 / 8-10分钟深度）

如果用户已经提供了以上信息，直接开始。

---

## 平台特性差异（按需调整语气和节奏）

| 平台 | 特点 | 节奏 | 语气 |
|------|------|------|------|
| **YouTube** | 中长视频为主，观众耐心高，重视信息密度和专业度 | 可以慢一点，讲透 | 专业但不死板，像技术博主跟粉丝分享 |
| **B站** | 弹幕文化，观众喜欢有深度的内容，接受较长视频 | 中等节奏，留弹幕点 | 可以带点梗和幽默，但不能浮夸 |
| **小红书** | 图文+短视频，女性用户多，重视画面和实用感 | 快节奏，30秒内出核心 | 温暖、实用、像闺蜜/朋友推荐好物 |
| **抖音** | 短视频为主，前3秒定生死，完播率是核心指标 | 极快，信息密度拉满 | 直接、有冲击力、制造好奇心 |

## 整体结构（必须遵循）

每个脚本必须包含以下三个部分：

### 一、爆款构思

- **核心定位**：一句话说清楚"这条视频要告诉观众什么"，必须有一个尖锐的观点
- **标题备选**：至少提供 3-4 个标题，建议用户 A/B 测试
- **爆款要素设计**：开头怎么抓人、中段怎么留住人、结尾怎么引导互动

### 二、正式脚本

分章节写，每个章节标注时间戳或时长，包含：
- 画面指令（用斜体括号，如 `*（画面：对着镜头，语气沉稳）*`）
- 口播台词（用 `>` 引用格式）
- 插入画面提示（用 `*（插入画面：xxx）*`）

### 三、结尾 + 拍摄建议

- 结尾必须有明确的行动号召（点赞/收藏/评论/关注）
- 附带封面设计建议、评论区置顶文案、标签建议

---

## 核心写作原则（从用户反馈中提炼，必须遵守）

### 语气与措辞

1. **口语化，像跟朋友聊天**。不用书面语，不用"首先其次最后"这种结构。用"你看"、"对吧"、"简单说"这类词拉近距离。
2. **克制使用绝对化表达**。不用"没有之一"、"吊打"、"碾压"这类词。可以用"最强"、"第一梯队"、"也许/可能是最好的"，留有余地更可信。
3. **不说无法验证的具体数字**。如果不确定，用"便宜"、"量大管饱"这种描述代替具体价格/时间。不要编造"一天只要几毛钱"这类可能有误的数据。
4. **敏感词替换**。"翻墙"用"魔法上网"替代，避免平台审核风险。

### 节奏控制

5. **开头 5 秒必须出核心信息**。不要铺垫，第一句话就告诉观众"这条视频在讲什么、跟我有什么关系"。
6. **背景介绍要短**。如果开头 Hook 已经点明了主题，不要再用大段篇幅重复介绍每个产品/概念是什么。用 2-3 句话快速带过，用"简单说两句"、"废话不多说"这种话术加速过渡。
7. **每个演示场景控制在 30-45 秒**。不要拖沓，给出"痛点 → 一句话指令 → 效果展示"的紧凑结构。
8. **场景要选有共鸣的**。优先选择普通用户日常会遇到的需求（如整理文件、做图表、处理数据），而不是小众场景。

### 技术准确性

9. **技术细节必须核实**。涉及模型映射、配置步骤、API 地址等技术操作，不要想当然，先搜索确认再写入脚本。如果不确定，宁可不写或标注"请以官方文档为准"。
10. **不要加入不必要的中转/第三方服务**。除非用户明确要求，只介绍官方直连方案，避免引入额外复杂度。

### 收尾设计

11. **场景演示结束后必须有一个价值升华总结**。不要演示完就跳到下一章。用一句话点明"这东西的真正价值是什么"，把认知从"聊天机器人"升级到"数字员工/工作流自动化"。
    - 参考句式："它不是'陪你聊天'，而是'帮你把活干完'"
12. **最终结尾金句**。用"用 AI 和不用 AI"的对比制造紧迫感。
    - 参考句式："未来淘汰你的不是 AI，而是会用 AI 的人"

## 开头 Hook 公式

好用的开头结构（三段式）：

1. **抛出判断**："X + Y，这也许是 Z 年普通用户最好的方案。"（制造好奇：凭什么？）
2. **快速画面轰炸**：闪过 2-3 个核心能力画面，每个停留 1 秒（视觉证明）
3. **消除顾虑 + 行动号召**："不用写代码 / 不用花大钱 / 不用魔法上网。几分钟搞定。先点赞收藏。"

---

## 场景演示公式

每个场景按以下结构写：

```
痛点（"你看我这文件夹，乱成什么样了"）
→ 一句话指令（"我直接跟它说：xxx"）
→ AI 执行过程（展示画面）
→ 效果展示 + 对比（"你自己干得一小时，AI 两分钟"）
```

## 避免的错误（用户已明确纠正过的）

| 错误做法 | 正确做法 |
|---------|---------|
| 大段介绍每个产品是什么 | 2-3 句快速带过，"废话不多说，直接上教程" |
| 写具体未核实的数字 | 用模糊但准确的描述（"量大管饱"而非"几毛钱"） |
| 手动模型映射等技术细节 | 核实后写"自动处理"而非教用户手动操作 |
| 加入可选的第三方中转服务 | 只写官方方案，除非用户要求 |
| 长篇避坑提醒 | 删掉，保持节奏 |
| "没有之一"等绝对化表达 | 删掉，留余地更可信 |
| "5分钟"等具体时间承诺 | 用"几分钟"代替 |
| "翻墙" | 用"魔法上网" |
| 场景演示完直接跳走 | 必须加价值升华总结段落 |
| "免费"但实际要花API费用 | 不说"免费"，说"便宜/划算" |

## 写作流程

1. 先了解主题，搜索相关资料，核实关键技术细节
2. 确定核心定位和标题
3. 按模板结构写完整脚本
4. 自查：是否违反了上方"避免的错误"表格中的任何项
5. 输出 .md 文件
